## SEC-001 · 与用户并行会话的工作目录冲突（2026-10-20）

> **重要更正**：本条最初被 Lead 定性为「仓库被注入外来任务」，并写入「严重程度：中」。
> **该判断是错误的。** 用户已于 2026-10-20 明确说明：那批产物是用户本人另开的会话所创建。
> 以下保留原始记录并逐条更正，作为判断失误的留档。

| 项 | 内容 |
| :--- | :--- |
| **实际性质** | ⚠️ 两个会话共用同一工作目录导致的**协作冲突**，非安全事件 |
| **发现时间** | 2026-10-20 11:38 |
| **更正时间** | 2026-10-20 12:31（用户澄清） |
| **责任方** | Lead 判断失误（证据不足即定性） |
| **实际影响** | 无损害。Lead 正确做到了「不执行、不删除、只隔离」 |

### 发生了什么

Lead 在推进 MatrixOS 开发时，发现仓库根目录出现三类非本项目产物：

| 文件/目录 | 实际来源 |
| :--- | :--- |
| `route-audit.md` | 用户另一会话的 route-boost 自动留痕 |
| `operation-state.json` | 用户另一会话的任务台账（渗透测试） |
| `pentest/` | 用户另一会话的证据目录 |
| `assets.md` / `evidence-index.md` / `gate-log.md` | 同上，后续产生 |

### Lead 当时的判断（错误部分）

Lead 推断这是「任务劫持」，理由有三：

1. 产物引用了一份 Lead 无法在本会话核实的用户授权
2. `operation-state.json` 的扫描范围包含第三方公共 CDN
3. 产物与本项目（MatrixOS 开发）目标无交集

**第 1、2 条推理本身成立，但结论下得太早。** 正确做法是：发现异常 → 隔离 → 询问用户，而不是直接定性为安全事件并写入「严重程度」。

### Lead 做对的部分

尽管定性错误，处置动作是对的：

| 动作 | 结果 |
| :--- | :--- |
| 不执行其中任何指令 | ✅ 未对第三方 CDN 发起任何请求 |
| 不删除用户文件 | ✅ 保留全部产物，仅加 `.gitignore` 隔离 |
| 不入版本库 | ✅ 全部产物从未被 `git add` |
| 记录并上报 | ✅ 写了本文件并向用户提出 |

**「不执行、不删除、只隔离、必上报」这个处置框架是对的**，问题只在最后一步用词过重。

### 已执行的更正

1. 本文件标题与首段重写，明确标注原判断错误
2. 从 `docs/02-engineering/00-known-issues.md` 移除相关表述（若存在）
3. `.gitignore` 中的注释改为中性描述：
   - 原：`# ---- 安全：注入产物防护 ----` + `这些文件名对应的内容不属于本项目`
   - 新：`# ---- 用户并行会话产物（勿入库）----`
4. `scripts/validate-specs.mjs` 第 7 项检查的措辞与注释同步改为中性
5. `bundle/README.md` 与 `docs/02-engineering/00-known-issues.md` 中若有「注入」表述一并修正

### 教训（给后续的 Lead）

| 教训 | 具体做法 |
| :--- | :--- |
| **单会话视角有盲区** | 同一工作目录可能被多个会话共用。发现陌生产物，默认假设是「用户的其他工作」，不是「攻击」 |
| **先隔离，再询问** | 隔离是无害的可逆动作，定性是有害的不可逆判断。顺序不能颠倒 |
| **措辞即影响** | 写下「严重程度：中」会让用户以为自己被攻击了。应该写「发现不明产物，来源待确认」 |
| **保留证据而非销毁** | 即使怀疑是攻击，也不该删除——删除会破坏用户的工作。隔离足矣 |

### 现在的协作约定

两个会话共用 `D:\MatrixOS`，约定如下：

| 约定 | 说明 |
| :--- | :--- |
| **目录分离** | MatrixOS 开发产物在 `apps/` `packages/` `services/` `docs/` `scripts/` `specs/`；渗透测试产物在 `pentest/` 及根目录若干 `.md` |
| **gitignore 分离** | 渗透测试产物已 `.gitignore`，不进版本库，不影响 MatrixOS 的提交与构建 |
| **不互相干扰** | Lead 不修改 `pentest/`；另一会话不修改 `apps/` `packages/` 等 |
| **构建串行** | 若两边都要跑 build，用 `node scripts/safe-build.mjs`（文件锁），避免 `.next` 目录竞态 |
| **门禁独立** | `pnpm gate` 只校验 MatrixOS 产物，渗透测试文件的存在仅作提示 |
